# Policies, Licenses, and Trademarks

## Recommended license matrix

### Code — Apache License 2.0

Use for:

- reference implementations;
- validators;
- CLIs;
- SDKs;
- website source where practical.

Reason:

- permissive commercial and noncommercial use;
- explicit patent grant;
- clear notice requirements;
- widely understood by implementers.

### Specification prose and documentation — CC BY 4.0

Use for:

- normative specification text;
- guides;
- diagrams;
- explanatory documentation;
- governance documents where appropriate.

Reason:

- permits reuse and adaptation;
- requires attribution;
- supports publication in other documentation systems.

### Schemas, examples, registry data — CC0 1.0

Use for:

- JSON Schemas;
- sample files;
- identifier tables;
- namespace registries;
- conformance fixtures where copyright friction would harm use.

Reason:

- machine-readable standards should be incorporable without uncertainty;
- examples are more useful when freely copied into tests and products.

### Brand — reserved

The Paper & Slate name, wordmark, icon, and official project marks are not licensed under the above content or code licenses.

## Repository notices

Every repository should contain:

- `LICENSE` for code;
- `LICENSE-DOCS.md` or equivalent;
- `NOTICE`;
- `TRADEMARKS.md`;
- file-level headers only where necessary;
- a README license summary.

## Trademark permissions

Allow without prior permission:

- “implements the Paper & Slate File System” when true;
- “compatible with Paper & Slate Discovery” when requirements are met;
- unmodified logo use linking to the official project;
- factual references in articles, education, and events;
- forks that clearly state they are unofficial.

Require permission or prohibit:

- naming a product “Paper & Slate [Product]” in a confusing way;
- modified official logos;
- implying endorsement or certification;
- using the mark on incompatible implementations without qualification;
- registering confusing domains or social handles.

## Policy inventory

Required before launch:

- Governance
- RFC Process
- Maintainers
- Contribution Guide
- Code of Conduct
- Security Policy
- Conflict-of-Interest Policy
- License Overview
- Trademark Policy
- Privacy Policy
- Accessibility Statement

Recommended after launch:

- Sponsorship Policy
- Incident Response Policy
- Data Publication Principles
- Conformance Mark Policy if conformance marks ever exist

## Review cadence

- Security: every six months
- Governance: annually
- Code of Conduct: annually or after incidents
- Trademark and licenses: annually and before legal incorporation
- Privacy: whenever providers or data collection change

## Disclaimer

All final legal policy text should receive qualified legal review before being represented as legal advice or a finalized legal instrument.
