## Standards and Formats

Each project receives a root with the same predictable shape:

```text
[Project]
├── Overview
├── Status and Roadmap
├── Learn
├── Guides
├── Reference
├── Specification
├── Examples
├── Tools
├── Migrations
├── Security and Privacy
└── Changelog
```

Hide empty sections rather than publishing placeholders.

## Tools and Libraries

## Page taxonomy metadata

Each page declares:

- `docType`;
- `projectId` when applicable;
- `normative`;
- `versionScope`;
- `audience`;
- `status`;
- `keywords`;
- `order`;
- `source` generated by ingestion.

## Naming rules

- Use nouns for concept/reference pages.
- Use verbs for task guides.
- Use exact project terminology.
- Avoid “Overview” as the title of unrelated pages; qualify it with the project in metadata and breadcrumb.
